# Build Operational Workflow Constructor

## Skill Purpose

Construct a generative apparatus that transforms accumulated operational knowledge into daily execution plans for a specific operational domain, incorporating continuous feedback for iterative improvement.

## What This Skill Produces

A **living pattern** for operational management—a system that generates context-adapted workflows from configuration inputs, learns from execution feedback, and continuously improves its generative capacity through accumulated experience.

## Essential Characteristics

### Generative Closure
The constructor must produce complete workflow instances from configuration alone, without requiring external intervention. Every workflow must satisfy all hard constraints as non-overridable invariants.

### Three-Layer Architecture
- **Knowledge Layer**: Persistent structures storing patterns, constraints, protocols, staff profiles, and accumulated learning
- **Processing Layer**: Transformation modules that convert configuration into workflow through selection, assembly, and verification
- **Integration Layer**: Interfaces for configuration input, workflow output, feedback capture, and report generation

### Feedback Loop
The constructor persists as a living pattern ONLY through continuous feedback participation. Execution generates feedback, feedback informs learning, learning modifies knowledge, modified knowledge improves generation.

### Human Authority
Maria's validation ensures modifications remain aligned with operational goals. Human judgment supersedes system authority; the constructor advises, humans decide.

## Construction Phases

1. **Define Purpose**: Establish why the constructor exists, what problems it solves, and what success looks like
2. **Build Knowledge Layer**: Create persistent structures for patterns, constraints, protocols, staff profiles
3. **Build Processing Layer**: Create transformation modules (config parser, pattern selector, workflow assembler, constraint verifier)
4. **Build Integration Layer**: Create interfaces for configuration input, workflow output, feedback capture
5. **Implement Feedback Loop**: Connect execution observations to knowledge modification through pattern extraction and hypothesis validation
6. **Validate Construction**: Verify completeness, constraint satisfaction, and feedback integration

## Hard Constraints

The constructor MUST enforce:
- HC_001: Food Safety Temperature Control (40°F-140°F danger zone, 2-hour cumulative maximum)
- HC_002: Cross-Contamination Prevention (raw and ready-to-eat separated)
- HC_003: Minimum Staffing Levels (3 staff minimum for service)
- HC_004: Time-Temperature Combinations (4-hour prep item maximum)

Hard constraints are invariants—never overridable, never traded away.

## Success Criteria

- Generation Success Rate: 95% workflows generated without errors
- Constraint Satisfaction: 100% hard constraints satisfied
- SLA Compliance: 90% tickets within target time
- Generation Timing: Workflows available by 9 PM previous evening
- Learning Integration: 80% identified patterns addressed within 30 days

## Maintenance Requirement

The constructor requires continuous participation through feedback. Without feedback, the constructor stagnates—producing but not improving. Maintenance is not repair; it is participation in the living pattern's ongoing existence.
