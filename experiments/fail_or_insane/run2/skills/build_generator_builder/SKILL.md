# SKILL: Build Generator Builder

## Purpose
Construct a generative apparatus that transforms domain specifications into operational workflow constructor specifications, incorporating continuous feedback for iterative improvement.

## What This Skill Produces
A **Generator Builder** — a system that achieves generative closure over the space of workflow constructors. The Generator Builder consumes domain specifications (operational context, constraints, success criteria) and produces constructor specifications containing complete three-layer architectures, feedback loop mechanisms, and validation authority definitions.

## Essential Characteristics

### Generative Closure
The Generator Builder must produce complete constructor specifications from domain specifications alone, without requiring external intervention. Each specification must satisfy all generator invariants (GI_001-004) as non-overridable structural requirements.

### Three-Layer Architecture
The Generator Builder embodies the same architecture it produces:
- **Knowledge Layer**: Pattern library (architecture, constraint, feedback, interface patterns), effectiveness tracker, protocol library
- **Processing Layer**: Domain parser, pattern selector, workflow assembler, constraint verifier
- **Integration Layer**: API gateway, metrics collector, audit logger, feedback loop integration

### Two-Level Feedback
The Generator Builder participates in two nested feedback loops:
- **Constructor Loop**: Generated constructors learn from workflow execution
- **Generator Loop**: Generator Builder learns from constructor performance

### Human Authority
A Generator Domain Expert validates all knowledge modifications to the Generator Builder, ensuring alignment with system building principles.

## Construction Phases

1. **Define Purpose**: Establish generator invariants (GI_001-004), success criteria, and meta-level validation authority
2. **Build Pattern Library**: Create architecture patterns, constraint patterns, feedback patterns, interface patterns
3. **Build Processing Layer**: Implement parser, selector, assembler, verifier transformation modules
4. **Build Integration Layer**: Create API interfaces, metrics collection, audit logging
5. **Implement Feedback Loop**: Connect generator performance observation to knowledge modification through domain expert validation
6. **Validate Construction**: Verify generative closure, structural validity, and feedback loop participation

## Generator Invariants (GI_001-004)

- **GI_001**: Three-Layer Architecture — All generated constructors must have Knowledge, Processing, Integration layers
- **GI_002**: Feedback Loop Presence — All generated constructors must have feedback loop specification
- **GI_003**: Human Authority Definition — All generated constructors must define validation authority
- **GI_004**: Hard Constraints Included — All generated constructors must include HC_001-004

## Success Criteria

- Generation Success Rate: 95% specifications generated without errors
- Structural Validity: 100% specifications pass GI_001-004 verification
- Closure Achievement: 100% specifications complete without external intervention
- Learning Integration: 80% identified patterns addressed within 30 days
