### B. The Loop Closure for This Instance

The Copper Beech Constructor's feedback loop must close to be effective. Closure requires that every phase connects to the next without gaps:

**Execute → Capture: Continuous Observation**

The execute phase must continuously generate observations for the capture phase. At The Copper Beech:
- Maria observes throughout service and records notable events
- Kitchen display system captures timestamps automatically
- Expo logs plate timing continuously
- Staff reports incidents as they occur
- All observations accumulated for weekly extraction

**Capture → Extract: Structured Processing**

The capture phase must transform raw observations into structured data for extraction. At The Copper Beech:
- Sunday morning, Maria reviews the week's accumulated observations
- Observations categorized as: pattern candidates, failure modes, edge cases
- Frequency analysis: How often has this been observed?
- Context analysis: What conditions accompanied the observation?
- Confidence scoring: How strong is the evidence?

**Extract → Validate: Maria's Review**

The extract phase must generate pattern candidates that are meaningful for validation. At The Copper Beech:
- Maria arrives Sunday at 9:00 AM
- System presents extracted pattern candidates
- Each candidate includes: description, frequency, context, confidence
- Maria applies validation criteria
- Maria renders decisions: accept, reject, modify, defer

**Validate → Modify: Authorization and Implementation**

The validate phase must render decisions that can be implemented by the modify phase. At The Copper Beech:
- Maria's decisions are documented with reasoning
- Implementation guidance recorded
- System updates knowledge base
- Next workflow generation uses updated knowledge

**Modify → Execute: Closed Loop**

The modify phase must update the knowledge base in ways that can be observed in subsequent execution cycles. At The Copper Beech:
- Updated patterns available for next day's generation
- Maria's protocol refinements incorporated
- Staff profile updates affect assignment logic
- Loop closes when tomorrow's workflow is generated with updated knowledge
