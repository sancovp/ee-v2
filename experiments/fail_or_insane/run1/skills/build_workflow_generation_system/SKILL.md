# Build Workflow Generation System

## Purpose
Construct a system that generates context-appropriate daily workflow instances for small commercial kitchens, transforming abstract design principles into concrete, executable specifications.

## Operating Definitions

### System Architecture
A workflow generation system is a **living_pattern** maintained through **feedback_loop** cycles: it observes kitchen execution outcomes, identifies what generation approaches succeed or fail, and incorporates these insights into improved generation algorithms.

### Three-Level Design Structure
The system embodies **three_levels** of design:
- **static_design**: The explicit generation rules, constraint specifications, and pattern libraries
- **dynamic_design**: Real-time generation adaptations to context changes
- **learning_design**: Mechanisms that enable the system to improve from execution feedback

### Generation Philosophy
The system operates as a **continuous_design** activity—not a one-time specification but a perpetual negotiation between generation algorithms and kitchen reality. Each generated workflow is both a production output and an experiment that generates data for system improvement.

### Improvement Trajectory
The system progresses through **improvement_trajectory** stages—from initial rule-based generation through validation accumulation and learning integration toward optimization and mastery. Improvement emerges from **feedback_loop** operating across multiple **time_scale** horizons.

### Positive Dynamics
The system exhibits **positive_dynamic** behaviors: competence flywheels where better generation enables clearer feedback, knowledge network effects where additions compound, and practitioner trust cycles where improved outputs increase engagement.

## Required Inputs

### Kitchen Context
- Physical layout: dimensions, station locations, flow paths, zone definitions
- Equipment inventory: types, capacities, positions, maintenance schedules
- Staff profiles: roles, skills, certifications, availability, cross-training
- Menu composition: items, recipes, workflow requirements, demand projections

### Design Parameters
- Optimization targets: speed vs. quality vs. efficiency weightings
- Design assumptions: staffing stability, equipment reliability, demand predictability
- Output preferences: verbosity level, visualization, formality

### Constraint Specifications
- Hard constraints: non-negotiable requirements (food safety, physical limits)
- Soft constraints: preferred conditions (timing windows, quality standards)
- Optimization targets: competing objectives to balance

## Output Specification

### Primary Output: Daily Workflow Instance
A complete, coherent workflow specification including:
- Station configurations with equipment assignments and capacity limits
- Prep schedules with timing, assignments, and dependencies
- Service flow with phases, firing sequences, and handoff protocols
- Role allocations with coverage patterns and backup relationships
- Communication protocols with calls, acknowledgments, and escalation paths
- Adaptation plans with contingency procedures and trigger conditions

### Supporting Outputs
- Station guides: setup, operation, and cleanup procedures per station
- Prep lists: detailed prep items with quantities, timing, and storage
- Timeline visualizations: Gantt charts or flow diagrams
- SOPs: standard operating procedures for critical processes

## Quality Criteria

### Fidelity Requirements
Generated workflows must faithfully embody:
- Transformation logic: material flows match recipe requirements
- Coordination logic: stations connected, handoffs clear, streams synchronized
- Adaptation logic: contingencies present, escalation pathways defined

### Operational Requirements
- Completeness: all necessary elements present
- Consistency: no internal contradictions or conflicts
- Feasibility: executable with available resources
- Safety: food safety constraints never violated

### Usability Requirements
- Comprehensibility: practitioners can understand and follow
- Actionability: immediately executable without interpretation
- Traceability: reasoning behind design decisions visible
