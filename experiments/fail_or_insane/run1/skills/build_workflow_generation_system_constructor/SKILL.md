# Build Workflow Generation System Constructor

## Purpose

Constructs workflow generation systems—living patterns that transform abstract kitchen contexts into concrete workflow instances. The constructor produces a generative apparatus, not a single workflow; it creates the *capacity to generate* appropriate workflows for diverse kitchen contexts through a configurable generative grammar.

## Scope

This skill orchestrates the construction of complete workflow generation systems comprising:

- **Knowledge structures**: Kitchen representations, constraint specifications, pattern libraries
- **Synthesis engines**: Generation algorithms that produce workflow instances
- **Feedback mechanisms**: Learning systems that enable continuous improvement
- **Output formatters**: Documentation and visualization generators
- **Three-level architecture**: Static design (explicit rules), dynamic design (real-time adaptation), learning design (feedback integration)

## Prerequisites

- Domain knowledge of small commercial kitchen operations
- Understanding of workflow design principles
- Familiarity with constraint specification
- Knowledge of pattern-based system construction

## Process Summary

The constructor transforms meta-specifications into deployable workflow generation systems through six integrated phases: specification definition, architecture assembly, knowledge configuration, feedback establishment, validation, and deployment preparation.

## Quality Criteria

Constructed systems must demonstrate:

- **Generative closure**: Systems can produce workflows that satisfy all hard constraints
- **Learning capacity**: Systems can incorporate feedback and improve over time
- **Context adaptability**: Systems can be configured for diverse kitchen contexts
- **Coherent architecture**: Three design levels function as unified field
- **Traceable generation**: Practitioners can understand and verify system outputs

## Integration

This skill builds upon the L0P2 skill `build_workflow_generation_system` and enables the L0P3 artifact `copper_beech_daily_workflow_instance`. It operationalizes the standing rule: system building constructs living patterns maintained through feedback loops.

---

*The constructor does not generate workflows directly; it generates the generator. This recursive capacity is the essential nature of the skill.*
